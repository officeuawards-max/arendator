# Arendator Awards — лендинг бронирования билетов

Новая версия страницы `aawards.ru/tickets`. Статичные HTML + CSS + JS, **без сборки и без зависимостей**.

**Покупки на сайте нет.** Все кнопки открывают форму бронирования. Заявка уходит на наш сервер, сервер создаёт **лид в Битрикс24**, дальше с ним работают менеджеры по продажам.

```
index.html                          ← вся разметка (блоки 01–11 подписаны комментариями)
assets/css/style.css                ← стили (все классы с префиксом aa-, конфликтов с Bootstrap нет)
assets/js/config.js                 ← НАСТРОЙКИ: адрес для заявок, цены, дата таймера, Метрика
assets/js/seating.js                ← СХЕМА ЗАЛА: столы, цвета зон, вместимость, координаты
assets/js/main.js                   ← логика: форма бронирования, схема, таймер, анимации
assets/img/                         ← фото и логотипы (список имён — в assets/img/README.md)
backend/laravel/TicketLeadController.php  ← приём заявки → лид в Битрикс24 (Laravel)
backend/bitrix-lead.php             ← то же самое одним PHP-файлом, без фреймворка
legacy/                             ← исходники старой страницы и картинка схемы — для сверки
```

## Как посмотреть

```bash
python3 -m http.server 8000   # из корня репозитория → http://localhost:8000
```
Пока `endpoints.lead` в `config.js` пустой, страница работает в демо-режиме: форма показывает «Спасибо», но ничего не отправляет (данные пишутся в консоль браузера).

## Бронирование → Битрикс24

### Кнопки
Любой элемент с `data-book` открывает одну и ту же форму с уже выбранным форматом:

```html
<button data-book="vip">Забронировать</button>        <!-- vip | business | personal | table -->
<button data-book="question">Задать вопрос</button>   <!-- форма без выбора формата -->
```

В форме: формат (4 варианта), количество гостей с ориентировочной суммой, ФИО, телефон (с маской), email, компания, должность, комментарий, согласие на обработку ПД и скрытое антиспам-поле.

### Что уходит на сервер
`POST {endpoints.lead}`, FormData, заголовки `X-CSRF-TOKEN` и `X-Requested-With`:

| Поле | Значение |
|------|----------|
| `intent` | `booking` или `question` |
| `package` | `vip` / `business` / `personal` / `table` (нет у вопроса) |
| `guests` | количество гостей, 1–50 (нет у вопроса) |
| `name`, `phone`, `email`, `company`, `position`, `comment` | данные из формы |
| `pol_agree` | `1` — согласие на обработку ПД |
| `utm_source` … `utm_term` | UTM-метки, запоминаются на время визита |
| `page`, `referrer` | страница заявки и откуда пришёл посетитель |
| `ym_client_id` | ClientID Метрики, если счётчик есть на странице |
| `website` | антиспам: у человека всегда пустое |

Ответ 2xx означает успех: гость видит «Спасибо! Заявка отправлена». Любой другой ответ показывает ошибку, и заявку можно отправить повторно.

### Что создаётся в Битрикс24
Метод `crm.lead.add`:
- **TITLE**: «Arendator Awards 2026 — Бизнес, гостей: 3» или «… — вопрос с сайта»
- **NAME, COMPANY_TITLE, POST, PHONE, EMAIL** — из формы
- **OPPORTUNITY**: цена × гости, `CURRENCY_ID=RUB`. Цены считаются **на сервере**, значениям из браузера не доверяем. У стола и вопроса суммы нет.
- **COMMENTS**: формат, гости, сумма, комментарий, страница, источник перехода, ClientID Метрики
- **UTM_SOURCE … UTM_TERM**, `SOURCE_ID=WEB`, `SOURCE_DESCRIPTION` = «Лендинг билетов aawards.ru/tickets»
- **ASSIGNED_BY_ID**: ответственный, если задан в настройках

Проверено на имитации Битрикс24: заявка с формы доходит до `crm.lead.add` со всеми полями выше. На реальном портале не проверялось.

### Подключение (Laravel, рекомендуется)
1. В Битрикс24 создать входящий вебхук: *Разработчикам → Другое → Входящий вебхук*, права — **только CRM**.
2. Скопировать `backend/laravel/TicketLeadController.php` в `app/Http/Controllers/`.
3. Добавить роут:
   ```php
   Route::post('/tickets/lead', [\App\Http\Controllers\TicketLeadController::class, 'store'])
       ->middleware('throttle:10,1')->name('tickets.lead');
   ```
4. В `.env`:
   ```
   BITRIX24_WEBHOOK=https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxxxxxxxxxx/
   BITRIX24_ASSIGNED_ID=            # необязательно
   ```
   В `config/services.php` добавить блок `bitrix24` (текст — в шапке контроллера).
5. В `assets/js/config.js` указать `endpoints.lead: '/tickets/lead'`.

**Без Laravel:** положить `backend/bitrix-lead.php` на сервер, задать переменную окружения `BITRIX24_WEBHOOK` и указать путь к файлу в `endpoints.lead`.

> ⚠️ Адрес вебхука — секрет. Он даёт доступ к CRM, поэтому **никогда** не вызывайте Битрикс напрямую из браузера и не кладите вебхук в `config.js` или в репозиторий. Только через сервер, как в файлах из `backend/`.

Если лид не создался, причина пишется в лог (`storage/logs` в Laravel или `error_log` PHP), вместе с данными заявки, чтобы её не потерять.

`…/tickets#book-vip`, `#book-business`, `#book-personal`, `#book-table`, `#book-question` сразу открывают форму с нужным форматом.

## Схема зала
План перенесён 1:1 с утверждённой картинки (`legacy/seating-plan.jpg`): стены, welcome-зона, бар, сцена, вход, колонна, 72 стола, подписи «до N чел», легенда.

**Схема справочная: выбрать конкретный стол нельзя.** Гость нажимает на стол и видит:
- цвет, то есть формат (ВИП / Бизнес / Персональные);
- стоимость за гостя;
- сколько гостей за столом;
- что входит;
- кнопку «Забронировать», которая открывает форму с этим форматом. Номер стола в заявку **не** передаётся.

Ещё есть фильтр по цветам, масштаб «+ / −», перетаскивание увеличенной схемы и подсказка при наведении. Белые столы — «Забронировано», как в легенде картинки; нажать на них нельзя.

**Где что менять:**
- `assets/js/seating.js` — столы: номер, зона, вместимость, координаты, `booked`, а также цвета и описание зон.
- Статичная часть плана (стены, бар, сцена, легенда) лежит в `index.html`, блок 06.
- Необязательно: `config.js → seating.statusUrl` — адрес, отдающий `{"booked": ["702", …]}`, чтобы белые столы обновлялись без правки файла.

Цвета зон взяты с картинки схемы: **ВИП — зелёный, Бизнес — розово-красный, Персональные — жёлтый.** Так же они показаны в карточках и таблице сравнения.

## Перенос в Laravel (Blade)

Лендинг больше не зависит от формы оплаты сайта. jQuery, iCheck и прочее не нужны, так что подойдёт любой вариант.

**Вариант А: внутри layout сайта**
1. Скопировать `assets/` в `public/landing/tickets/`.
2. `resources/views/tickets/landing.blade.php`:
   ```blade
   @extends('layouts.new.usercp')
   @section('styles')
       <link href="https://fonts.googleapis.com/css2?family=Manrope:wght@300;400;500;600;700;800&display=swap" rel="stylesheet">
       <link rel="stylesheet" href="{{ asset('landing/tickets/css/style.css') }}?v=1">
       {{-- + инлайн-скрипт из <head> index.html (подмена картинок и флаг анимаций) --}}
   @endsection
   @section('content')
       {{-- всё от <div class="aa"> до </div><!-- /.aa --> из index.html --}}
   @endsection
   @section('scripts')
       <script src="{{ asset('landing/tickets/js/config.js') }}?v=1"></script>
       <script src="{{ asset('landing/tickets/js/seating.js') }}?v=1"></script>
       <script src="{{ asset('landing/tickets/js/main.js') }}?v=1" defer></script>
   @endsection
   ```
3. Пути `assets/…` заменить на `/landing/tickets/…`.
4. В `<head>` должен быть `<meta name="csrf-token" content="{{ csrf_token() }}">`.
5. Если у layout своя шапка, блок `<header class="aa-nav">` можно удалить.

Все классы начинаются с `aa-`, сбросы стилей действуют только внутри `.aa`. Стили сайта и Bootstrap лендинг не ломают, и сам лендинг на сайт не влияет.

**Вариант Б: отдельная страница.** `index.html` как есть, с CSRF-мета, если заявки принимает Laravel.
