# Arendator Awards 2026 — лендинг бронирования билетов

Новая версия страницы **aawards.ru/tickets**: бронирование билетов на церемонию федеральной премии в области коммерческой недвижимости Arendator Awards. Церемония — **8 октября 2026, Москва**.

> 📘 **Подробная инструкция для IT-специалиста (как всё устроено, что и куда подключать, все тонкости):**
> **[ИНСТРУКЦИЯ_ДЛЯ_ИГОРЯ.md](ИНСТРУКЦИЯ_ДЛЯ_ИГОРЯ.md)**

---

## Коротко

- **Технологии:** статичные HTML, CSS и JS. **Без сборки и без зависимостей** (нет npm, jQuery, фреймворков). Серверная часть нужна только для приёма заявки, готовые обработчики лежат в `backend/`.
- **Покупки на сайте нет, только бронирование.** Все кнопки ведут к форме «Оформление билета». Заявка уходит на наш сервер, сервер создаёт **лид в Битрикс24** (`crm.lead.add` через входящий вебхук).
- **Дизайн — по макету дизайнера:** чёрный с золотом, светлые кремовые блоки, плавные CSS-анимации.
- **Шрифт — только Roboto** из файла заказчика (`assets/fonts/source/Roboto.rar`), лежит локально. Других шрифтов на странице нет, стрелки и галочки нарисованы SVG и CSS.
- **Схема зала — утверждённая, 72 стола.** Выбирается **зона** (VIP / Business / Персональная), а не стол. Номер стола не показывается в карточке и не уходит в заявку. Фиолетовые столы — «Места закончились», их не забронировать. На компьютере схема горизонтальная (сценой вверх), на телефоне вертикальная.
- **152-ФЗ (редакция 2025–2026):**
  - отдельное согласие на обработку ПД (галочка не отмечена заранее);
  - необязательное согласие на рассылки;
  - политика ПД и политика cookie;
  - cookie-баннер, Метрика только после согласия;
  - журнал согласий на сервере.

## Структура

```
index.html                  ← разметка (блоки подписаны комментариями)
assets/css/style.css        ← стили: классы aa-*, сбросы только внутри .aa, конфликтов с Bootstrap нет
assets/js/config.js         ← НАСТРОЙКИ: адрес для заявок, цены, дата таймера, остаток мест, Метрика, реквизиты
assets/js/seating.js        ← данные схемы зала: зоны, цвета, столы, координаты
assets/js/consent.js        ← cookie-баннер, согласие на аналитику, реквизиты оператора
assets/js/main.js           ← логика: форма и отправка лида, схема, слайдеры, таймер, анимации
assets/fonts/               ← Roboto (woff2) + исходный архив заказчика source/Roboto.rar
assets/img/                 ← фото (что где — assets/img/README.md), оригиналы в originals/
legal/                      ← Политика ПД, Согласие на ПД, Согласие на рассылки, Политика cookie
backend/laravel/TicketLeadController.php  ← заявка → лид в Битрикс24 (Laravel)
backend/bitrix-lead.php     ← то же одним PHP-файлом без фреймворка
legacy/                     ← старая страница (Blade) и утверждённая картинка схемы — для сверки
ИНСТРУКЦИЯ_ДЛЯ_ИГОРЯ.md     ← полная инструкция по запуску и подключению
```

## Посмотреть локально

```bash
python3 -m http.server 8000     # из корня репозитория → http://localhost:8000
```

Пока в `assets/js/config.js` пуст `endpoints.lead`, форма работает в **демо-режиме**: показывает «Спасибо», но ничего не отправляет, а данные заявки пишет в консоль браузера.

## Запуск — главное

1. **Битрикс24:** создать входящий вебхук с правами только CRM. Адрес вебхука хранить **только на сервере** (`.env` или переменная окружения), никогда в JS и не в git.
2. **Сервер:** установить обработчик из `backend/` (Laravel-контроллер или PHP-файл) и указать его адрес в `config.js → endpoints.lead`.
3. **Перенос в Blade:** заменить относительные пути на абсолютные. На адресе `/tickets` без слэша относительные пути ломаются, подробности в инструкции, раздел 9.
4. **Метрика:** счётчик запускать только после согласия на cookie (код в инструкции, раздел 14.4). Завести цели `tickets_book_open` и `tickets_book_sent`.
5. **Цены** менять в двух местах: `config.js → tickets` и `PACKAGES` в обработчике из `backend/`.
6. **Проверка:** пройти чек-лист из инструкции, раздел 18.

Все подробности — в **[ИНСТРУКЦИЯ_ДЛЯ_ИГОРЯ.md](ИНСТРУКЦИЯ_ДЛЯ_ИГОРЯ.md)**.
